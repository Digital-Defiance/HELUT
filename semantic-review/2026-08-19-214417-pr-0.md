# Protocol-v2 durability for the P1030680 Mulein campaign

The change adds protocol-versioned run identity, exact ordered-prefix resume, per-row validation, candidate host/scoring replay, and durable prior-gate handling to the P1030680 TensorLUT campaign. Four correctness gaps remain in that boundary: a loaded row does not prove its candidate set, valid-tail recovery reorders rows, the run hash can bind different manifest bytes from those executed, and post-gap validation omits the wholly-after-gap condition.

Watch for: **confirmed** candidate deletion can erase a durable gate while preserving a valid row; **confirmed** a complete final row without its newline is moved ahead of the prefix; **confirmed** manifest hashing and decoding use separate reads; **confirmed** the loader admits post-gap entries whose crib overlaps the declared missing span.

**Verdict**: NEEDS_CHANGES

## High-level view

Chunk admission checks each row against the next exact plan element and replays every persisted candidate. It only shape-checks `completeReceiptDigest`, so it cannot establish that all expected receipts were represented or every hit was retained; a gated candidate can be removed while the row still suppresses that chunk on resume.

The ledger rejects non-prefix rows and rows after a gate, but crash recovery decodes a newline-less final record before preceding lines. A multi-row ledger ending in a complete JSON object without `\n` therefore fails exact-prefix validation even though every record is intact.

Protocol v2 is included in the run-ID payload, and canonical ciphertext is checked before ledger opening. The manifest SHA and manifest object come from independent file reads, so a concurrent replacement can make the identity describe one byte stream while planning and materialization execute another.

Family labels, edit forms, receipts, geometry replay, and the inventory fingerprint are checked. The post-gap loader does not mirror the builder's `transmittedOffset >= delta` invariant, allowing a semantically straddling entry to be labeled as wholly post-gap.

## A complete row does not commit to its full hit set

**High severity, confirmed.** `p1030680ValidateChunkRecord` verifies only that `completeReceiptDigest` has the `fnv1a64-` shape, then checks `positiveCount == candidates.count` and replays candidates that remain (`Sources/HELUTToolKit/P1030680MuleinCampaign.swift:698-741`). It cannot recompute the digest because the row stores no receipt projection for negative jobs or independently checkable hit bitmap. Removing a gated row's `candidates`, setting `positiveCount` to zero, and clearing `breakGatePassed` leaves every predicate true; the unchanged digest is accepted. On restart the chunk is complete, the prior gate disappears, and later evaluator work can run.

Persist enough per-job receipt semantics to recompute the complete digest and derive the hit/candidate set during load. Derive `positiveCount` and `breakGatePassed` from that committed set instead of mutually consistent row fields; add authentication or an externally anchored hash chain if deliberate coherent edits must also be detected.

## A valid newline-less tail is validated before its prefix

**Medium severity, confirmed.** When the file lacks a final newline, the initializer pops and decodes the tail and immediately appends it to `rows` (`P1030680MuleinCampaign.swift:219-228`). It appends preceding newline-delimited segments afterwards (`:240-252`). With at least two rows, an intact final JSON object whose newline was lost becomes row zero and is compared with `expectedPlan[0]`, rejecting the valid prefix.

Decode retained segments first and append the decoded tail last, or hold it separately until prefix parsing completes. Add a two-row/no-final-newline regression alongside malformed-tail truncation.

## Run identity can hash a different manifest than the one executed

**High severity, confirmed.** Startup reads `manifestData`, then `MuleinFutureManifestBuilder.load(path:)` reads the path again (`P1030680MuleinCampaign.swift:904-909`). The run payload hashes the first value while taking fingerprint/count and planned work from the second (`:805-812`). If the path is atomically replaced between reads, fields omitted from the inventory fingerprint—such as tolerance and plug policy—can change while the run ID still matches an earlier run. Candidate-free earlier rows can then validate and be skipped under different execution semantics.

Decode, validate, materialize, and hash one immutable snapshot. A `load(data:sourcePath:)` entry point removes the split; avoid a file-backed mapped snapshot if delayed hashing can observe mutation.

## Post-gap family validation omits the after-gap boundary

**Medium severity, confirmed.** The builder requires every post-gap representative to have `transmittedOffset >= delta` (`Sources/HELUTToolKit/MuleinFutureManifest.swift:191-195`), making the crib wholly after the missing group. The loader checks the family, label, and missing span but not the evidence offset (`:318-327`). A separately produced entry can overlap the span, materialize consistently, pass receipt/fingerprint checks, and still count as post-gap.

Require `entry.evidence.transmittedOffset >= manifest.delta` for the post-gap suffix and cover `delta - 1` and `delta` boundaries.
