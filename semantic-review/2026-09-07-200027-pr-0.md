# E256-vNext rotor/schedule rejection bake-off

This change adds a deterministic rejection campaign for two rotor families, two candidate schedules, one common-endpoint control, and five depths, recorded as an OPEN research receipt. `make e256-vnext-bakeoff-check` reproduces digest `8d286b74126428ba927215d3627592433660783895d604f905f53d5f6e9655e5`; the 38,400-map count, core exact diagnostics, and quotient algebra match the implementation. The audit retains no security-selected depth, keeps AEAD-only as the production boundary, and moves no C/H/N row. The result cannot yet be treated as execution of the frozen preregistration because KDF domains diverge, required corpus cases are absent, and the control gate bypasses candidate rejection.

Watch for: **confirmed** preregistration/runner KDF drift; **confirmed** omission of the preregistered 32-bit boundary and identifiable reset-context test; **confirmed** controls that can pass without validating campaign detectors.

**Verdict**: NEEDS_CHANGES

## High-level view

The reported dimensions are accurate: 30 cells contain 1,280 states each, yielding 38,400 maps; 20 candidate cells account for 25,600 states. These remain bounded failures to reject, not security claims.

The frozen JSON is authenticated but is not the executable source of truth (**confirmed**). Only counters, adjacent pairs, status, and active depths are connected to it; the remaining contract is hardcoded, and the executed rotor subkey names already differ. The corpus reaches the 16-bit transition but not the mandatory 32-bit transition, so eligibility omits a hard rejection test (**confirmed**).

Several positive controls construct expected collisions directly rather than injecting defective derivation into the metrics and `select()` path (**confirmed**). The null covers only part of the exact rejection suite, and the declared PRF-mask-only and AEAD-only baselines never run (**confirmed**).

The depth-specific state digest includes inactive rotor material (**confirmed**). The present 1+1 baseline satisfies the frozen priority, but the lexical fallback can select the wrong schedule, family, or depth after a rejection (**confirmed**).

The check binds the runner, preregistration, predecessor artifacts, and complete deterministic payload, but not the architecture record that defines D0–D11 (**confirmed**). The audit’s OPEN, non-production, no-C/H/N posture otherwise matches the receipt.

### The frozen preregistration is authenticated but not executed

**High severity, confirmed.** `verify_frozen_inputs()` authenticates the preregistration and compares only status and active depths (`Scripts/e256_vnext_bakeoff.py:1212-1233`). `run_candidates()` reads only counters and adjacent pairs (`Scripts/e256_vnext_bakeoff.py:901-906`); families, schedules, replications, key labels, streams, directions, sequence, diagnostic subsets, controls, and selection rules remain hardcoded.

Current output already reflects drift. The frozen KDF names `rotor/in` and `rotor/out` (`directives/e256-vnext-bakeoff-preregistration.json:72-73`), while `RotorBank` derives `rotor/ingress` and `rotor/egress` (`Scripts/e256_vnext_bakeoff.py:294-298`); the declared `controls` subkey is also unused. The preregistration hash authenticates a declaration but cannot make differently domain-separated output conform to it.

Derive operational values from validated fields or assert every hardcoded equivalent before metrics run. Reconcile the KDF labels deliberately, then regenerate the receipt and audit; updating only the expected hash would preserve the mismatch.

### Eligibility skips a mandatory counter boundary

**High severity, confirmed.** Hard rejection requires 16-bit and 32-bit boundaries, reset contexts, and directions (`directives/e256-vnext-bakeoff-preregistration.json:389-397`). The corpus stops at 65,536 and fixes sequence 7 (`directives/e256-vnext-bakeoff-preregistration.json:184-222`; `Scripts/e256_vnext_bakeoff.py:1303-1312`): it has no 4,294,967,295/4,294,967,296 pair or declared sequence-reset pair.

`select()` can therefore retain a schedule that aliases at the absent boundary. Add the 32-bit pair and explicit distinct canonical reset contexts, assert each required pair was evaluated, and only then state that all 20 cells avoided the preregistered exact detectors. Direction separation is already exercised.

### Planted controls bypass the candidate detector path

**High severity, confirmed.** `duplicate_rotor_bank` hashes one duplicated table; `truncated_counter_8` uses a standalone low-byte function; `direction_omitted` returns one derivation for both directions; and `ignored_key_bit` clears the bit on both inputs (`Scripts/e256_vnext_bakeoff.py:669-742`). None injects the defect into `derive_state_material()`, collision accounting, `key_flip_collision_check()`, or `select()` (`Scripts/e256_vnext_bakeoff.py:901-1182`). A detector regression can coexist with `all_planted_controls_detected=true`.

The ideal null checks map duplication, affine maps, involutions, and adjacent signatures, but not commutator, direction, key-flip, state-collision, or full selection behavior (`Scripts/e256_vnext_bakeoff.py:749-783`). Feed defective schedule/family/derivation implementations through the same summarization and selection code and assert their rejection reasons; direct expected-value booleans do not validate the interpretation gate.

### Two declared comparison baselines never run

**Medium severity, confirmed.** The preregistration declares `ideal_independent_state`, `prf_mask_only`, and `aead_only`, and Q4 asks for retention relative to the latter two (`directives/e256-vnext-bakeoff-preregistration.json:280-294`). The runner creates only 64 ideal-independent permutations (`Scripts/e256_vnext_bakeoff.py:749-776`); no PRF-mask-only arm, AEAD-only complexity record, or compromise-model comparison enters the payload.

The conservative production verdict does not promote a candidate, but it does not answer Q4 or support the claim that the complete preregistration ran. Add those records and comparison, or mark them as non-executed policy references and narrow the frozen question and execution claim.

### Depth-local state collisions include inactive material

**Medium severity, confirmed.** `effective_state_bytes()` serializes all 16 IDs and wrappers from each bank at every depth, then appends active-depth A and B maps (`Scripts/e256_vnext_bakeoff.py:479-491`). In a focused check, changing only the sixteenth ingress-ID slot left the 1+1 `F` map identical but changed its “effective state” digest. Thus identical active 1+1 states can be counted as distinct because unused suffixes differ.

Map collision counting still catches byte-identical active maps, so current map eligibility is unchanged. The state counts remain depth-inaccurate; serialize material only through active depth or relabel this as a full 16-depth derivation-transcript digest.

### The architecture authorization remains mutable

**Medium severity, confirmed.** The payload stores the architecture path and hardcoded D0–D11 names (`Scripts/e256_vnext_bakeoff.py:1290-1299`), but `verify_frozen_inputs()` never hashes `directives/e256-vnext-topology.md`. Its constraint definitions can change while the payload remains identical and `--check` passes.

The executable and result artifacts are otherwise hash-bound and the complete payload is compared (`Scripts/e256_vnext_bakeoff.py:1404-1418`). Verify an architecture SHA-256 and include it beside the path so the interpretation contract cannot drift silently.

### The fallback baseline violates the frozen priority

**Low severity, confirmed.** The tie-break requires full-counter schedule, then tableless family, then smallest depth (`directives/e256-vnext-bakeoff-preregistration.json:410-412`). The runner special-cases the current preferred cell and otherwise uses `sorted(eligible)[0]` (`Scripts/e256_vnext_bakeoff.py:1177-1183`). If preferred 1+1 alone is rejected, lexical order can choose `16+16` before `2+2`; other rejection patterns can put family before schedule.

The current 1+1 result is not overclaimed. Replace the fallback with a structured schedule/family/numeric-depth rank and test cases where the first cell or family is rejected.

### 38,400 maps and the common-endpoint quotient

The scope is `16 keys × 2 families × 3 schedules × 2 streams × 2 replications × 2 directions × 10 counters × 5 depths = 38,400`. For fixed endpoints, `F_m = B ∘ T_m ∘ A`, hence `F_m ∘ F_n^-1 = B ∘ T_(m xor n) ∘ B^-1`: unequal masks give a fixed-point-free involution with 128 transpositions, while equal masks give identity and a map collision. `related_record()` uses that composition convention. DDT excludes zero input difference, LAT excludes zero masks, and the ANF Möbius transform matches the declared diagnostics.
