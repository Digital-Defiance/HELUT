# Cost-selected Shannon DAG lowering for multilinear LUTs

The change replaces the always-expanded sum of minterms with a planner that compares that form against a reduced Shannon DAG and searches variable orders through LUT width six. The intended result is fewer MPSGraph UInt32 arithmetic nodes without changing the polynomial represented by a LUT. Variable remapping, low/high cofactoring, and modulo-2^32 reassociation are exact for constant-fill tensors, including arbitrary non-Boolean UInt32 values. Two **confirmed** regressions prevent the broader all-encoding, all-input equivalence claim: phase-shaped constants are not componentwise ring identities, and projection terminals can alias tensors that downstream result dictionaries bind to distinct buffers. The native baseline keeps compilation and cold specialization outside its timers and retains the same circuit, assignments, outputs, and digest work.

Watch for: **confirmed blocker** — `.phase` and `.glweTrivial` can differ from the previous polynomial away from valid encoded pads; **confirmed blocker** — reduced projection LUTs can make output or DFF result bindings overwrite each other.

**Verdict**: NEEDS_CHANGES

## High-level view

The planner remaps truth-table address bits into the chosen variable order, then deinterleaves even and odd entries as low and high cofactors. This agrees with the LSB-addressed Yosys convention. With a componentwise one tensor, grouping minterms gives `(1 - x)L + xH = L + x(H - L)` in the UInt32 residue ring, preserving the old polynomial for every input.

A **confirmed blocker** is that `encodedConstant(1)` is `[1, 0, …]` for `.phase` and `.glweTrivial`, while the new recurrence assumes a scalar identity. Arbitrary padded coefficients therefore follow a different polynomial. Packed GLWE bypasses the planner and retains the expanded body lowering.

A second **confirmed blocker** comes from terminal reduction. A multi-input projection can return an existing input tensor directly; output and next-state collection use dictionaries keyed by `MPSGraphTensor`, so separate logical destinations for that object overwrite one another.

The memoization key includes recursion depth and the remaining truth vector, correctly limiting sharing to a common variable suffix. The factored cost walker mirrors its emitter, but a **confirmed optional design issue** remains in the fallback metric: it counts only referenced complements while the expanded emitter constructs one for every input.

The native comparison still times the same scopes. Planning runs inside `compiler.compile`, the cold graph run remains excluded, historical HELUT samples wrap only synchronized `graph.run`, and paired samples run from assignment regeneration through ordered output digest. The semantic workload is unchanged; the optimized HELUT graph intentionally performs fewer internal arithmetic operations.

## Shannon remapping and the missing encoded-identity factor

`reorderedTruthTable` maps ordered bit `d` back to `variableOrder[d]`, and `splitFactoredValues` takes even addresses as low and odd addresses as high. Each recursion therefore removes the same original variable whose tensor it selects. The `(depth, values)` key cannot share a subfunction over a different remaining variable set.

Over `R = Z/(2^32)`, grouping the old minterms on one variable gives

```text
(C - x)L + xH = C·L + x(H - L)
```

where `C` is `encodedConstant(1)`. The new emitter at `Sources/HELUTCore/HELUTCore.swift:613-707` uses `L + x(H - L)`. This is exact for arbitrary inputs when `C` is the componentwise ring identity, as it is for `.constantFill`; modular wrap preserves the ring identity. An independent model checked every nonconstant truth table through width three, every permutation, and every input tuple over `{0, 1, 2, UInt32.max}`—97,992 comparisons—with no mismatch for `C = 1`.

The **confirmed blocker** appears in phase padding, where `C = 0`. For OR `[0, 1, 1, 1]` at a padded coefficient with `x0 = 0` and `x1 = 5`, the old expanded minterms return `0`; the selected identity-order DAG has low `x1`, high `C`, and returns `5 + 0·(0 - 5) = 5`. `TrivialPhaseEncoding` creates this sparse one tensor at `Sources/HELUTCore/TFHESeam.swift:181-185`, and `.glweTrivial` uses the same phase-shaped body. Restrict factoring to componentwise-one encodings, or derive terminal reductions and costs from `C·L + x(H-L)`.

Valid phase/trivial-GLWE Boolean wires keep padded inputs at zero, explaining why Boolean validation passes. The all-input claim and the source comment calling this “exactly the expanded polynomial” are still false. `.glwePacked` is unchanged because `compilePacked` continues through `compileMultilinearOnBodies` at `HELUTCore.swift:461`; PBS and encrypted backends also bypass this path.

Width zero and constant tables return before planning; width one reaches only terminal forms. Widths through six search all permutations, while wider tables keep identity order. These boundaries preserve the constant-fill proof and avoid recursion or factorial edge failures.

## Projection terminals collide with result-buffer binding

The new `lowConstant == 0 && highConstant == 1` terminal returns `input`, and `low == high` can reduce to the same tensor. A width-two projection `[0, 1, 0, 1]` now returns `x0` with no arithmetic, whereas the previous width-two expansion produced a distinct tensor.

The **confirmed blocker** occurs when the source and projected wires are both observed, or when projected values feed multiple next-state destinations. `bindTickResultBuffers` assigns separate buffers through `resultsDictionary[entry.tensor] = data` at `HELUTCore.swift:1452`, followed by state bindings keyed the same way; the native comparison likewise uses `results[entry.tensor]` at `NativeBaselineComparisonTests.swift:750`. Only the last destination survives for one tensor key, while earlier logical results retain unwritten or stale buffers. This is a new multi-input trigger even though width-one identity LUTs could already expose the underlying binding weakness.

Emit a distinct identity/copy for a LUT result that collapses to an upstream tensor, or deduplicate result tensors and make every logical output/state consume the populated data. Add direct-output plus width-two-projection coverage and the analogous DFF-state case.

## Memoized cost versus emitted expanded nodes

The factored emitter and cost walker use the same terminal order, `(depth, values)` sharing, and one cached complement per original variable. Recursive depth always increases, so cache construction cannot cycle; sharing stays LUT-local.

The **confirmed optional design issue** is that `expandedMultilinearOperationCount` at `HELUTCore.swift:758-771` counts `requiredComplements`, while `compileExpandedMultilinear` at `HELUTCore.swift:568-578` emits every input complement. For two-input AND, both modeled costs are one, so strict `<` selects expanded; its builder issues two disconnected subtractions plus the live multiplication, while the factored builder issues only the multiplication. MPSGraph may prune those nodes from execution, but the metric is not an emitted-node count and still adds graph-construction work. Lazily emit complements or document/count live dependencies rather than emitted operations.

## Native baseline remains outside planner work

`NativeBaselineComparisonTests` uses degree-one `.constantFill` and calls `compiler.compile` at line 616 before cold or measured runs. The cold run at line 794 is excluded. Historical samples at lines 804-813 wrap only `graph.run`; paired samples at lines 838-856 begin before `refillInputs` and end after output decode and ordered digest. Native models and workers are also created before their loops, while native paired timing includes assignments, evaluation, output materialization, and digest.

No per-trial work moved across a boundary. The circuit, lane assignments, lane points, trial count, outputs, and native work are unchanged; only the arithmetic graph inside the timed HELUT run is reduced. `NativeBaselineComparisonTests.swift` is untracked rather than present on `main`, so this conclusion comes from current-source inspection and execution rather than a textual base comparison.

## Boolean validation leaves the ring contract uncovered

The **confirmed coverage gap** is that no changed test differentially compares factored and expanded MPSGraph outputs on arbitrary UInt32 tensors, forces a non-identity best order, checks operation counts, or exercises aliased terminal results. The all-row full adder uses Boolean values and symmetric tables, `BatchLaneDistinctTests` stays on encoded Boolean points, and the native baseline uses degree-one `.constantFill`; none can expose the two blockers.

Add coefficient-level differential tests with wraparound-heavy inputs, exhaustive small truth tables/permutations, and targeted wider witnesses such as `[0, 1, 1, 0, 0, 0, 0, 0]`, whose best width-three order is non-identity. Result binding needs a separate graph-level alias test because polynomial comparison treats returning `input` as correct.

Validation run here: `git diff --check main -- Sources/HELUTCore/HELUTCore.swift` and `swift test -c release --filter NativeBaselineComparisonTests` passed; all benchmark lane points matched both Verilator digests. The arithmetic model passed all 97,992 `C = 1` comparisons and reproduced the `C = 0` OR counterexample (`expanded = 0`, `factored = 5`).
