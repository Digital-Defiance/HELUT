# E256 schema-3 center migration over a validated v2/gen0 base

Task 2’s recurrence repair and task 3’s native-NLFF/profile freeze remain reproducible: the independent LFSR/NLFF checks and deterministic emitter pass. Task 4 is not integrated: Swift now selects a schema-3, pre-step-dependent center, while the hand RTL, frozen fragment, committed golden, and TensorLUT derivatives still describe task-3/schema-2 behavior. The release build succeeds, but the E256 suite has five assertion failures and the passing core simulation exercises only the stale bundle. No task-4 row is ready to close.

Watch for: **confirmed, Critical** active Swift and hardware center semantics diverge; **confirmed, Critical** the committed golden is schema 2 and retains 90 reflector fixed points; **confirmed, Critical** E256-003 has no design/attack receipt for the one-bit reserved-pair center; **confirmed, Critical/High** profile capture, domain binding, table ingress, and KAT authority remain incomplete.

**Verdict**: NEEDS_CHANGES

## High-level view

The corrected right-shift/LSB recurrence and native reversible NLFF remain a coherent task-2/task-3 base. Schema-3 canonicalization agrees across `Enigma256Generation`, `Fixtures/enigma256_generation.json`, `Scripts/e256_nlff_emit.py`, and `enigma_256_nlff_v2.vh` on hash `2a9f54…`, but no wider artifact set is coherent under that identity.

Swift derives center mode from the four pre-step NLFF bits, conditionally opens the reserved `0↔1` pair, and advances with the same captured mask. The hand core and frozen fragment do not implement that branch, while the 36-byte golden has no branch coverage and cannot expose the difference.

`Enigma256Context` now captures a profile, but ambient profile reads and profile-independent MAC/handshake domains remain. The table validator checks useful invariants, yet fixture and MMIO ingress still traps or bypasses those checks.

The evidence is structural and bounded, not a confidentiality or deployment result. There is no independent implementation, strict long-form KAT, external cryptanalysis, or complete protocol/hardware hardening.

## Task-2 recurrence and task-3 NLFF remain reproducible

Within the failed 40-test E256 run, the known-vector, inverse, rank-64, maximal-order, long-checkpoint, and nonzero-trajectory recurrence tests passed. `./Scripts/enigma256_lfsr_sim.sh` independently matched through clock 1,024, directly revalidating E256-001 and most of E256-042.

`python3 Scripts/e256_nlff_emit.py --check` reproduced profile hash `2a9f54c70a1619805a911758158f1e2204b0fd96c35102a9db5f4575aeb40cb0` and receipt hash `5c5bc9…`; `./Scripts/enigma256_nlff_sim.sh` matched fourteen fixed vectors, and the Swift balance/first-order-correlation checks passed. This preserves the current closure basis for E256-004, E256-007, and E256-010, although this pass did not rerun the full candidate search.

## Schema-3 center stops at the Swift boundary

**Critical severity, confirmed.** Swift computes `step_r1 XOR step_r2 XOR step_r3 XOR step_r4`, replaces the reserved base-reflector pair with identity in mode one, and captures one pre-step mask for scrambling and stepping (`Sources/HELUTCore/Enigma256.swift:157-166`, `:282-286`). The base reflector deterministically reserves `0↔1` after shuffling values 2…255 (`Enigma256.swift:504-514`).

The hand core still performs unconditional `reflector[r4_out_fwd]` (`enigma_256_core.v:118-122`). The RTL fragment uses the old nibble-swap/XOR un-reflector (`enigma_256_scramble_frag_combo.v:118-136`), and its Swift oracle has no LFSR/mode input (`Sources/HELUTToolKit/Enigma256TensorLUT.swift:212-235`):

```text
schema-3 Swift machine ── pre-step parity ── reserved-pair center
hand RTL core          ──────────────────── base reflector only
Swift/RTL fragment     ──────────────────── historical stand-in UKW
```

The paths diverge when mode is one and the forward path reaches center input 0 or 1. A deterministic schema-3 zero-plaintext probe first reached that condition at byte 714; no checked-in RTL vector reaches it.

## Committed artifacts still certify schema-2 fixed points

**Critical severity, confirmed.** The active profile declares schema 3/hash `2a9f54…` (`Sources/HELUTCore/Enigma256Generation.swift:154-168`; `Fixtures/enigma256_generation.json:1-4,125-133`). The golden session/parameters and both generated TensorLUT derivatives declare fixture-v2/hash `6734d5…` (`Fixtures/enigma256_golden/session.json:4-13`; `Fixtures/enigma256_golden/tb_params.vh:1-4`; `enigma_256_tensorlut_baseline.v:1-4`; `enigma_256_step_cone_tensorlut.v:1-4`). The session omits schema-3 center/reflector fields required by `loadAndVerify`, so the current loader rejects it before parity (`Sources/HELUTCore/Enigma256Bridge.swift:196-238`).

A full read-only table check found 90 reflector fixed points, `reflector[0] == 0`, `reflector[1] == 0xe9`, and 16 unchanged bytes in the 36-byte ciphertext (`Fixtures/enigma256_golden/tables/reflector.hex:1-256`; `Fixtures/enigma256_golden/session.json:1-3`). JSON, `.bin`, and `.hex` ciphertext copies are mutually consistent only with this interim behavior.

The hand core passes all 36 committed bytes because both sides are old. More subtly, a newly generated 36-byte schema-3 bundle was also reproduced by an old-center model because the conditional pair was never reached. Regenerating the same short vector cannot certify task 4.

## Functional reciprocity does not close E256-003

**Critical severity, confirmed.** The Swift maps are involutions: mode zero has no center fixed points and mode one has two; using one captured pre-step mask preserves stream reciprocity. The Swift-only formal check and 2,000-state bijection sweep pass those structural properties.

E256-003 still needs a reviewed per-position construction, Swift/RTL parity, and equality evidence near `1/256`. The two-map, one-bit schedule is an alternative with no construction review or attack receipt; the NLFF search receipt does not grade the center. A 100,000-byte zero-plaintext SoftBus probe measured 0.38% equality, but there is no null interval, repeated key/nonce set, differential threshold, or known-broken positive control. Runtime text still says zero plaintext should remain unchanged around 30% and labels rates much greater than `1/256` as expected (`Sources/HELUTToolKit/Enigma256Commands.swift:772-784`, `:860-885`).

The deterministic reflector also inherits the known modulo bias in Fisher–Yates (`Enigma256.swift:469-470`, `:505-514`), as does rotor selection (`:407-410`). Schema 3 currently binds that open E256-012 behavior.

## Profile capture and domain separation stop halfway

**Critical/High severity, confirmed.** `Enigma256Context` captures a value profile and passes its day/message domains (`Sources/HELUTCore/Enigma256Session.swift:78-104`), but `Enigma256Generation.current` remains mutable and `nonisolated(unsafe)` (`Sources/HELUTCore/Enigma256Generation.swift:189-190`). Direct LFSR, KDF, machine, CoreHandle, bridge, TensorLUT, and configuration paths still default to or read it (`Sources/HELUTCore/Enigma256.swift:39-40`, `:364-400`; `Sources/HELUTCore/Enigma256Session.swift:142-145`, `:201-216`; `Sources/HELUTCore/Enigma256Bridge.swift:77-79`, `:223-238`). E256-005 is partial.

Only day/message labels include the profile hash (`Sources/HELUTCore/Enigma256Generation.swift:377-383`). MAC, ECDH, and hybrid domains remain `enigma256-mac-v1`, `enigma256-ecdh-v2`, and `enigma256-hybrid-v1` (`Sources/HELUTCore/Enigma256AEAD.swift:19-22`; `Enigma256ECDH.swift:49-70`; `Enigma256Hybrid.swift:31-35`). A body/tag produced under the same IKM and salt therefore authenticates independently of which E256 profile will interpret it. E256-006 remains partial.

## Wiring validation does not protect ingress

**High severity, confirmed.** `Enigma256Wiring.validate` checks permutation, plugboard involution, rotor inverse, fixed-point-free reflector, and reserved-pair invariants (`Sources/HELUTCore/Enigma256.swift:48-55`, `:96-138`). Its length error is effectively unreachable through the preconditioned initializer, while `wiring(fromTables:)` and `parseHexMEM` also trap; generic hex decoding silently maps malformed bytes to zero (`Sources/HELUTCore/Enigma256Bridge.swift:111-139`, `:327-336`). Machine construction converts validation failure into another precondition (`Sources/HELUTCore/Enigma256.swift:248-251`).

SoftBus burst loading validates by trapping, beat loading stages unchecked tables until `pulseLoadState`, and real MMIO falls back to unchecked byte writes (`Sources/HELUTCore/Enigma256Session.swift:159-193`; `Sources/HELUTCore/Enigma256AXI.swift:51-69`, `:90-93`). No negative table vectors exercise these boundaries. E256-025 and the relevant E256-028 work are partial.

## Short same-authority tests cannot detect center drift

**High severity, confirmed.** The golden has 36 final bytes but no KDF intermediates, artifact hashes, or internal checkpoints (`Sources/HELUTCore/Enigma256Bridge.swift:69-91`, `:288-320`). Its unit test writes a fresh temporary bundle and reloads the same writer’s output; it neither checks the committed bundle nor invokes an independent authority (`Tests/HELUTTests/Enigma256Tests.swift:226-243`). There are no center-mode vectors, same-mask Swift/RTL traces, 1,024-byte stream KATs, duplicate-format checks, or malformed-input vectors.

`swift test -c release --filter Enigma256Tests` built successfully but ran 40 tests with five failures: stale center expectations at `Enigma256Tests.swift:143` and `:154`, schema-2 expectations at `:541` and `:558`, and a no-op schema mutation at `:616-620`. The certificate samples four machine states and still states that the reflector may have fixed points (`Sources/HELUTCore/Enigma256Formal.swift:62-68`, `:153-170`). Its passing result is not evidence for E256-026, E256-029, E256-044, E256-045, or E256-046.

## Exact closure validation

E256-003 requires an approved rationale and profile-bound specification, exhaustive two-mode byte-map checks, and vectors forcing both reserved-pair inputs under both modes. Swift, hand RTL, the fragment, post-Yosys netlists, and TensorLUT derivatives must agree beat-for-beat for at least 1,024 bytes on pre-step mask, center input/mode/output, offsets, and LFSR. Chosen-plaintext equality/differential campaigns need repeated deterministic keys/nonces, a calibrated `1/256` interval, and the historical fixed-point center as a positive control.

E256-005/E256-006 require removing global cryptographic defaults, making profile identity mandatory at every context/bridge/SoftBus/TensorLUT/handshake/traffic/fixture boundary, and testing that global/default changes cannot affect an existing stream. Day, message, center/schedule, MAC/traffic, handshake, and fixture domains must bind family/suite/generation/profile hash; v1, schema-2, wrong-profile, wrong-direction, and cross-session opens must fail before decryption.

E256-025/E256-028 require throwing table constructors and strict Codable/hex parsers with exact lengths, canonical hex, resource limits, no zero substitution, and negative vectors for every permutation, inverse, involution, fixed-point, and reserved-pair violation. Rejection must precede real MMIO writes or core activation.

E256-026/E256-027/E256-029 require canonical profile bytes/hash, KDF intermediates, table/artifact hashes, basis recurrence vectors, state checkpoints at 0/1/2/58/59/60/64/128/1,024, at least 1,024 stream bytes, explicit center-branch vectors, and rejection vectors. Deterministically regenerate to a temporary directory and byte-compare the committed bundle, verify every duplicate format, regenerate every recurrence/center-bearing artifact, and run source/post-synthesis/Swift parity from one manifest. `python3 Scripts/e256_nlff_emit.py --check`, `./Scripts/enigma256_lfsr_sim.sh`, `./Scripts/enigma256_nlff_sim.sh`, the full E256 Swift suite, core/AXI/AXIS RTL tests, and TensorLUT synthesis/parity must all pass against schema 3.

E256-042 still needs an explicit zero-state rejection/remapping policy and external-zero negative vectors. E256-044/E256-045 require treating `ent` only as a smoke test, committing calibrated chosen-plaintext/differential receipts with positive controls, and mechanizing only the universal finite-table/reciprocity claims. E256-012 requires a reviewed uniform bounded sampler and another profile/hash freeze.

## Security claim ceiling

There is no basis for an “unbreakable,” “wartime-ready,” production-ready, or expert-endorsed claim. Active software semantics are absent from hardware, E256-003 remains open, the committed KAT has the older fixed-point center, the E256 suite fails, and no independent implementation or external cryptanalysis exists. `directives/e256-audit.md:3-6`, `:122-124`, and `:172` explicitly keep E256 experimental, not for real data, and prohibit those claims.
