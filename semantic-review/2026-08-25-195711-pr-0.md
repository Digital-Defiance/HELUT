# Profile-bound TensorLUT controls and immutable battery receipts

The change adds current, planted-easy, and contradictory-null roles to the E256 TensorLUT optimizer and replaces both shell batteries with one profile-bound runner. The score construction is coherent, outcome language stays bounded and in-sample, and the historical seven-arm matrix remains intact beside an explicit bounded profile. The receipt path is not ready to rely on: it can execute a stale or changing binary, an interrupted run can publish `status: pass`, and several scientific claims are trusted rather than independently checked. The planted controls work on both current cones, but their pre-optimization defect is not part of the pass condition and the whole containing LUT remains mutable.

Watch for: **confirmed, High** the manifest does not bind one executed binary to the reviewed source; **confirmed, High** `KeyboardInterrupt` can produce an incomplete summary marked `pass`; **confirmed, High** the planted receipt omits its pre-optimization defect and describes a whole-LUT melt as a one-entry control; **confirmed, High** result validation omits lambda and independently recomputed score/verdict checks; **confirmed, Medium** dot-only run IDs escape or collapse the intended run namespace; **confirmed, Low** both wrappers advertise bounded arms while invoking the full profile by default.

**Verdict**: NEEDS_CHANGES

## High-level view

The canonical chromosome scores `0` on the ordinary target and `-1` when one duplicated row has one expected bit flipped. Identical inputs force identical outputs, so the contradictory pair has best soft score `-0.5` and best binary score `-1`; the `>-0.05` survival threshold cannot produce a legitimate null survivor. Its pass predicate remains only a no-false-positive check and accepts any optimizer failure.

The planted role selects the narrowest output-driving LUT, changes entry zero to `0.5`, freezes every other LUT, and requires an in-sample fit plus exact restoration of that entry. Focused probes scored the initial NLFF and scramble-fragment plants at `-336.0` and `-220.5`, confirming both are observable today. The production receipt scores only the untouched canonical baseline, while the per-LUT mask permits all 64 entries in the selected LUT to mutate.

Current-role red pressure fails the battery under its hold expectation, control failures exit nonzero, and reports explicitly deny security or work-factor meaning to blue holds. Fresh directories, exclusive artifact creation, copied netlists, and hashes prevent accidental run reuse, but the executable itself is neither rebuilt nor copied into the run.

The full profile preserves the historical `hard0`, `seedA`, `seedB`, `lam1`, `lam3`, `longex`, and `fatpop` tuples exactly and remains the default. `--budget-profile bounded` selects a separate seven-arm checkpoint matrix. The shell comments incorrectly label their default full invocation as bounded.

1. **Executable is not source-bound — confirmed, High** — a stale `.build/release/helut` is reused and a mutable external path is executed for every arm. Build or independently identify the artifact, copy it into the run directory, execute that copy, and bind it to the reviewed source/diff.
2. **Interrupted runs can report pass — confirmed, High** — `KeyboardInterrupt` bypasses `except Exception` but still writes the `finally` summary with the initial `pass` status. Derive success only from a complete, valid row set and mark interruption failed before re-raising.
3. **Planted control is not self-proving — confirmed, High** — the pass condition never verifies that the planted seed worsens fitness, and all entries in its LUT are mutable despite one-entry wording. Record and gate on the planted seed score/non-binary count, then add entry-level freezing or relabel and verify a one-LUT melt.
4. **Results are self-certified — confirmed, High** — the runner omits `polish_lambda`, role-specific baseline/contradiction fields, finite-number checks, and independent survival recomputation. Validate every matrix parameter and derive verdict/control outcomes from raw report metrics.
5. **Null control overstates optimizer calibration — confirmed, Medium** — any non-survival passes, including catastrophic or non-finite output. Require finite metrics and describe it specifically as a no-false-positive/verdict-plumbing control unless an expected null-quality bound is preregistered.
6. **Run ID can alter the namespace — confirmed, Medium** — `.` and `..` pass validation and collapse or escape the profile/run directory component. Reject dot components and enforce resolved-path containment.
7. **Receipt edge paths lack regression tests — confirmed, Medium** — no supplied test covers stale binaries, tampered fields, interruption, dot IDs, or current-role red pressure. Add runner-level tests for each fail-closed branch.
8. **Wrapper budget label is wrong — confirmed, Low** — both wrappers say bounded but inherit the runner’s full default. Correct the comments or explicitly select the bounded profile.

<details><summary>Details</summary>

## The planted receipt does not prove the positive control was live

`Enigma256TensorLUT.swift:570-586` softens entry zero and applies a LUT-granular `freezeAllExcept`; the other 63 entries in that LUT remain mutable. `plantedExactRecovery` checks only the selected entry (`Enigma256TensorLUT.swift:709-725`). Exact in-sample output constrains exercised sibling entries, not the unexercised remainder.

**Confirmed, High:** the preregistered baseline uses untouched `chromo.inits`, not `exploreSeedInits` (`Enigma256TensorLUT.swift:593-609,701-703`). Nothing requires the plant to worsen fitness or start with exactly one non-binary mutable entry. Current probes establish a real defect on both supplied netlists, but that evidence is absent from the immutable report and will not guard a newly synthesized cone. Add a finite `planted_seed_crypto` gate and either entry-level masking or one-LUT-melt language and checks.

## The contradictory null is mathematically impossible but one-sided

The duplicate input with one flipped expected bit makes the canonical `-1` baseline correct (`Enigma256TensorLUT.swift:484-506`). **Confirmed, Medium:** `controlPass = baselineSanityPass && !survived` accepts arbitrary optimizer failure (`Enigma256TensorLUT.swift:701-726`); existing NLFF receipts pass with scores near `-548037`/`-523407` and thousands of non-binary entries. This is valid only as a no-false-positive control, not evidence that the optimizer approached the null optimum. Require finite metrics and narrow the calibration wording.

## The executable hash does not establish source provenance

**Confirmed, High:** `resolve_binary` builds only when the configured binary is absent or non-executable (`Scripts/enigma256_tensorlut_battery.py:147-157`). The manifest hashes porcelain status rather than dirty contents and records an external binary path/hash without archiving it (`Scripts/enigma256_tensorlut_battery.py:188-197`). A stale binary can therefore represent new source, and a concurrent replacement can make later arms differ from the manifest hash. Pin one copied executable for all arms and record enough clean-tree or patch/runner provenance to reconstruct it.

## Fail-closed summary handling misses interruption

**Confirmed, High:** `status` starts as `pass`, only `except Exception` changes it, and `finally` always writes the summary (`Scripts/enigma256_tensorlut_battery.py:437-496`). Ctrl-C raises `KeyboardInterrupt`, which bypasses that handler but executes `finally`, allowing `completed_rows < expected_rows` alongside `status: pass`. Compute success from completeness and row validity in `finally`, with explicit interruption handling.

## The runner trusts the executable’s interpretation of its own results

The runner validates identity, netlist hash, role, scope, generations, population, seed, and the executable’s `baseline_sanity_pass` (`Scripts/enigma256_tensorlut_battery.py:293-307`), then trusts its `verdict`, `squeeze_survived`, and `control_pass` (`Scripts/enigma256_tensorlut_battery.py:310-341`). **Confirmed, High:** it never checks reported `polish_lambda`, so `lam1`/`lam3` can be mislabeled, and it does not verify role-specific baseline expectations, `contradictory_rows`, objective thresholds, or consistency with finite final metrics. Reject non-finite values and independently recompute survival and role outcomes before writing a passing row.

## Run-path and budget-profile labels diverge from behavior

**Confirmed, Medium:** `RUN_ID_RE` permits `.` and `..`, which are placed directly in `profile_tag / run_id / cone` (`Scripts/enigma256_tensorlut_battery.py:21,388-395`). Reject those components and check that the resolved path remains below the resolved profile root.

**Confirmed, Low:** both wrappers advertise bounded arms but forward only `--cone`, while the runner defaults to full (`Scripts/enigma256_red_battery.sh:2-6`, `Scripts/enigma256_scramble_frag_battery.sh:2-6`, `Scripts/enigma256_tensorlut_battery.py:382-384`). The matrix definitions themselves preserve full history and keep bounded execution explicit; align the comments with that behavior.

## Validation gaps are concentrated in receipt failure paths

Release compilation reached the changed Swift target; Python bytecode/help parsing and `bash -n` passed. Focused one-generation probes confirmed both planted defects, and existing bounded receipts contain the expected four controls plus seven current arms per cone.

**Confirmed, Medium:** no supplied automated test exercises stale-binary reuse, report-field mismatch/non-finite values, `KeyboardInterrupt`, dot-only run IDs, or current red-pressure termination. Add isolated runner tests with a fake executable so every pass/fail summary invariant is deterministic.
