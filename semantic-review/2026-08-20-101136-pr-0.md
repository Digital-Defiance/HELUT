# Protocol-v3 durable replay with one remaining ledger-writer gap

The v3 hardening closes all four findings from the prior pass: complete receipt projections make hit and gate state replayable, valid newline-less tails retain prefix order, one manifest byte snapshot drives hashing and execution, and post-gap entries must begin beyond the declared delta. Exact-prefix admission and the durable prior-gate halt also remain intact. One safety boundary is still open because ledger recovery and append are not protected against a second campaign process.

Watch for: **confirmed, Medium** concurrent runners can validate the same prefix and write through independently positioned handles, risking overwritten or malformed durable rows.

**Verdict**: NEEDS_CHANGES

## High-level view

Protocol v3 now derives completion from the planned full receipt set rather than trusting row summaries: it reconstructs canonical jobs, recomputes the digest, enforces exact hit↔candidate correspondence, replays candidates, and derives the BREAK gate. Tail recovery, manifest snapshotting, post-gap admission, prefix ordering, and prior-gate stopping all close the previously demonstrated failure modes.

**Confirmed, Medium:** the JSONL protocol still assumes one writer without enforcing that assumption. Each process can validate the same prefix, open its own handle at the same EOF, and race the next planned append.

## Replayable v3 rows close the four prior defects

The candidate-deletion hole is closed. Header validation requires the planned number of receipt projections (`Sources/HELUTToolKit/P1030680MuleinCampaign.swift:738-750`); each projection is range-checked and restored into its expected job (`:671-722`); and strict `(setting, seed)` ordering with exact tags makes the fixed-size set complete (`:761-783`). Validation then recomputes the digest, consumes one exact-key candidate for every hit, rejects candidates on misses, host/scoring-replays each candidate, and derives both positive count and gate (`:784-839`). Deleting a gated candidate, clearing its hit, or editing the gate without a matching replayable receipt now fails admission.

The tail-order defect is closed because `decodedTail` is held until all newline-delimited prefix segments decode, then appended last (`P1030680MuleinCampaign.swift:237-274`); its missing newline is restored only after ordered-prefix validation (`:306-312`). The manifest TOCTOU is closed because startup reads one `manifestData`, decodes and materializes from it, and hashes that same value into run identity (`:1001-1004`, `:1043-1047`; `Sources/HELUTToolKit/MuleinFutureManifest.swift:250-252`). Post-gap admission now requires `transmittedOffset >= manifest.delta` (`MuleinFutureManifest.swift:319-328`). Loaded row `n` is validated against plan element `n`, new rows only against `nextPlanIndex`, and a replayed prior gate returns before evaluator work (`P1030680MuleinCampaign.swift:276-320`, `:324-352`, `:1108-1116`).

## Parallel runners can invalidate the durable prefix

**Medium severity, confirmed.** The ledger reads the path at `P1030680MuleinCampaign.swift:231`, completes recovery and plan validation, then independently opens a writing handle and seeks once to EOF at `:307-308`. Appends use that retained handle at `:324-350`; no advisory lock, exclusive-open flag, or other ownership mechanism surrounds the lifecycle.

Two processes can therefore accept the same `N`-row prefix, both set `nextPlanIndex = N`, and evaluate plan element `N`. Their file descriptions retain independent offsets, so a write can replace or overlap the other process’s row, and neither runner rechecks disk before advancing its in-memory index. A later restart will usually fail closed on malformed or mismatched data, but only after duplicate work or loss of a durable receipt.

Acquire a nonblocking exclusive sidecar or ledger lock before the initial read/repair and hold it through final close; append mode alone would not protect plan ordering. `swift build` completed and `swift test --filter MuleinFutureTests --quiet` passed 10/10, but those tests do not exercise process-level writer contention.
