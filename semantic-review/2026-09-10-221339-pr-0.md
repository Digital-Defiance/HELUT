# Frozen H2 integrated-cost receipt overstates contract compliance

The H2 tranche adds six fixed-`R=12` integrated research tops spanning three storage organizations and fixed versus commit-sampled H4 wiring, then banks functional, cycle, hierarchy, storage, and generic ABC measurements in one deterministic receipt. Its RTL/model values, mutation controls, accounting, measured numbers, and canonical digest reproduce, while the text retains the non-production and standard-AEAD boundaries. Two frozen validity obligations remain unmet: fixed tops run beyond their preregistered 24-output corpus, and all-input initiation interval is inferred from one configuration. Watch for: **High, confirmed — 27,648 diagnostic fixed-model comparisons include 27,576 non-frozen observations but are excluded from the “executed total”; High, confirmed — one initiation-interval probe is promoted to an all-input H2P5 result.**

**Verdict**: NEEDS_CHANGES

## High-level view

A common configuration protocol feeds iterative fixed/direct cores over stationary FF, rotating FF, and generic-memory stores. Every 3,328-bit effective-mask store remains inside the measured boundary; the direct path adds one commit-sampled 12-bit H4 tuple that is held across rounds and blocks.

**High, confirmed:** each of 9,216 result rows contains all six variants. That is the frozen corpus for each direct top, but it gives each fixed top 9,216 observations instead of 24; the gate model-checks those extras, omits them from the reported executed total, and marks coverage exact.

**High, confirmed:** latency is checked on every row, while initiation interval is sampled only after configuration zero with blocks zero and one. The receipt converts that one cycle row into singleton sets and `input_independent: true` for all variants, leaving H2P5’s “for every input” obligation unproved.

Recursive accounting, complete storage categorization, and exact mapped-before/flattened-after primitive preservation remain intact. Cross-top fixed/direct evidence uses matching storage-preserved signatures for common modules and records, rather than equates, independent ABC mappings. This supports reproducible whole-flow deltas but not selector-only physical attribution, which the banking text explicitly disclaims.

The surfaces preserve `OPEN_PROGRESS`, make no architecture, round-count, XOF, H4-policy, vendor-memory, timing, production, security, or C/H/N selection, and keep reviewed standard AEAD mandatory. Their exact-coverage and input-independence claims must be regenerated after the validity gate is repaired.

## The fixed variants run outside their frozen 24-output corpus

**High, confirmed.** The preregistration freezes 24 outputs per fixed variant, 9,216 per direct variant, and 27,720 RTL/model comparisons, then requires exact executed variant/material/block/H4/comparison/cycle sets (`directives/e256-hardware-h2-preregistration.json:291-303`). A mismatched comparison or cycle set is a hard rejection (`directives/e256-hardware-h2-preregistration.json:450-452`). The frozen arithmetic is 72 fixed comparisons plus 27,648 direct comparisons.

The testbench starts all six variants for every selected configuration (`Hardware/Testbenches/Research/E256H/e256h_h2_integrated_core_tb.v:388-470`) across 1,152 configurations and eight blocks (`Hardware/Testbenches/Research/E256H/e256h_h2_integrated_core_tb.v:611-618`). Each fixed top consequently emits 9,216 observations: 9,192 extra per top, or 27,576 beyond the fixed corpus. `grade_functional` checks all 27,648 fixed observations against the model but counts only the 72 fixed-tuple records in `total_model_comparisons` (`Scripts/e256_hardware_h2_gate.py:1100-1174`).

The receipt exposes `diagnostic_fixed_model_comparisons_not_in_frozen_total: 27648` beside `executed_total_rtl_model_comparisons: 27720` (`logs/e256-hardware-h2-gate.json:565-576`). Yet `functional_coverage_exact` is assigned from byte equality (`Scripts/e256_hardware_h2_gate.py:2582-2591`), and frozen-input validation checks the aggregate count without enforcing `fixed_h4_outputs_per_variant` or `direct_h4_outputs_per_variant` (`Scripts/e256_hardware_h2_gate.py:701-705`). `CHECK PASS` therefore reproduces a corpus that the frozen exact-set rule says to reject.

Keep fixed starts to the three-material/eight-block fixed-H4 corpus, retain the full direct corpus, and derive/enforce per-variant counts from observed records. Optional redundant diagnostics must run outside the frozen receipt. Regenerate the receipt, digest, architecture result, audit row, and reproduction expectations afterward.

## H2P5 turns one initiation-interval sample into an all-input result

**High, confirmed.** H2P5 freezes latency and initiation constants “for every input in each variant” (`directives/e256-hardware-h2-preregistration.json:301-303,424-427`). Latency 12/14 is checked on every emitted row, but `measure_initiation_intervals` runs once after `configure_all(0)`, uses blocks zero and one, and shares one FF/ring and one memory interval across fixed/direct variants (`Hardware/Testbenches/Research/E256H/e256h_h2_integrated_core_tb.v:514-605`).

The runner parses one cycle row, constructs each II set from that value, unconditionally emits `input_independent: True`, and records `cycles_row_count: 1` (`Scripts/e256_hardware_h2_gate.py:956-1002,2447-2464`). H2P5 passes by comparing each singleton with its declared constant, without an input-keyed observation population (`Scripts/e256_hardware_h2_gate.py:2355-2363,2396-2402`). The receipt reports those extrapolated singleton sets (`logs/e256-hardware-h2-gate.json:442-559`) and marks `cycle_sets_exact: true` (`logs/e256-hardware-h2-gate.json:4131-4134`).

This finding concerns evidence, not a demonstrated data-dependent FSM. Record earliest reacceptance throughout the frozen corpus, or add a frozen machine-checked structural/formal proof of the universal cycle property. Derive `input_independent` and H2P5 from that evidence, then regenerate the receipt and banking text.
