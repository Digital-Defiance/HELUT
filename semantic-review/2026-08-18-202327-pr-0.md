# Scalar exact-first Mulein closure with one-edge repair

The change adds a scalar RTL lane that evaluates all 26 central-letter seeds, computes a reciprocal partial plugboard to fixed point, applies an optional plug-pair budget, and—only after exact failure—tries one active edge erasure at a time. The state machine preserves the exact run's candidate set across contradiction and over-budget retries, rejects reduced menus that detach the central letter, and exposes packed survivor/provenance receipts through a combinational descriptor-to-trail read chain. Icarus passes the supplied fixtures, a separate minimal fixture completed all seeds in 910 cycles with 26 closures, and Yosys accepted `read_verilog`, `proc`, and `check -assert`; no blocking RTL closure defect was demonstrated. There are two blocking verification findings: recorded failures exit Icarus successfully, and four-state `X` results are accepted by the test oracle.

Watch for: **confirmed** false-success termination and X-permissive assertions; **confirmed** gaps around full-mask/exact-first behavior, active-only enumeration and attachment/retry sequencing, and upper packed indices/protocol boundaries; **confirmed** CWD dependence in the compatibility wrapper.

**Verdict**: NEEDS_CHANGES

## High-level view

Each seed imposes `sigma(central)=seed` and reciprocal `sigma(seed)=central`, then scans every menu edge forward and reverse until no pair is added. Contradiction or an over-budget exact closure snapshots the edges that wrote state or exposed the contradiction. Each candidate is consumed before relaunch while the original bitmap survives trial resets, so failed trials advance through the exact-run candidates rather than replacing them with a partial retry set.

Attachment is checked against every surviving descriptor before reduced closure. The edge index is held across separate forward/reverse cycles, and the descriptor step directly drives the combinational trail address; Icarus and Yosys both accepted the packed variable accesses. This interface intentionally requires zero-latency descriptor and trail responses rather than synchronous RAM semantics.

**Confirmed:** the directed tests inspect only seeds 0 and 1, record failures in an integer, and use final provenance as a proxy for candidate enumeration. Wrong outputs outside those bits can print `PASS`; targeted `X` outputs also satisfy the assertions; and any recorded failure returns process status zero.

**Confirmed:** the root compatibility file works from the repository root but fails when passed by absolute path from another working directory because the nested include resolves from the invocation CWD.

## Icarus treats the suite's failure branch as success

**High severity, confirmed.** `check_condition` and timeout handling only increment `errors` (`Apps/Mulein/tests/rtl/mulein_closure_core_tb.sv:98-105`, `:156-165`). The nonzero-error branch calls `$finish(1)` (`:238-243`), whose argument controls diagnostic verbosity rather than process status. A standalone intentional-failure check printed the failure and returned Icarus status 0, so a Make/CI recipe that relies on `vvp` status can accept a broken core.

Replace the failure branch with `$fatal(1, "...")` or a harness-specific nonzero-exit mechanism verified under Icarus; retain `$finish` only for success.

## Four-state unknowns are silently accepted as passing results

**High severity, confirmed.** `check_condition` uses `if (!condition)` (`Apps/Mulein/tests/rtl/mulein_closure_core_tb.sv:98-105`). When an equality or output bit evaluates to `X`, `!condition` is also `X`, and a procedural `if` does not enter the failure branch; an isolated Icarus check produced `errors=0` for `condition=1'bx`. The polling loop and timeout test use the same two-state-style predicates on `done` (`:156-165`), so `done=X` can end the wait without recording a timeout, after which `config_error=X` and X-valued mask/provenance assertions also pass.

Fail unless each assertion is exactly true, for example `if (condition !== 1'b1)`, and poll with `while (done !== 1'b1 && ...)` followed by `if (done !== 1'b1)`. Apply exact four-state checks to `busy`, `config_error`, masks, and packed erasure values in the added protocol tests.

## The suite does not validate all 26 seed results or exact-first provenance

**Medium severity, confirmed.** The exact fixture checks only `survivor_mask[1]` and treats `closure_count == 26` as evidence for all seeds (`Apps/Mulein/tests/rtl/mulein_closure_core_tb.sv:204-210`); the other jobs inspect only seed 1 or seed 0 (`:212-235`). A core can execute 26 closures while producing wrong survivor bits for seeds 2-25. No exact survivor is inspected during a tolerance-1 job, so eager erasure of an already-valid exact result is also invisible.

Compare complete 26-bit survivor and erased-seed masks against a golden model, plus every relevant packed erasure slot. Add a tolerance-1 fixture containing an exact survivor whose erasure bit must remain clear, and repair seed 25 to exercise the highest `[(seed_cursor * EDGE_BITS) +: EDGE_BITS]` selection at `Apps/Mulein/rtl/mulein_closure_core.sv:381-386`.

## Final provenance does not prove active-only enumeration, attachment rejection, or every retry path

**Medium severity, confirmed.** The contradiction fixture claims to catch blind candidate enumeration but only checks the final successful edge (`Apps/Mulein/tests/rtl/mulein_closure_core_tb.sv:229-235`). A core that unnecessarily tries inactive, central-attached edge 1 before eventually accepting edge 2 still passes; disconnected edge 3 follows the successful edge in index order, so `erased_edge(0) != 3` does not prove it was absent from the candidate set. `drop_trial_count > 0` (`:217-222`) gives no per-seed candidate evidence. Both repairs retain another central incident edge (`:169-200`), and the plug-budget repair succeeds on its first candidate, leaving attachment rejection and plug-failure retry sequencing untested.

Expose or bind a per-seed trial bitmap/count, then add an inactive central-attached edge that must not be tried, a lowest-index active deletion rejected for detaching the central letter, and an over-budget seed whose first attached candidate remains over budget before a later candidate repairs it. Cross-check tolerance 1 against a blind all-single-edge oracle to validate the completeness contract at `Apps/Mulein/rtl/mulein_closure_core.sv:38-45` and retry transitions at `:350-430`.

## Start/done, shared-read timing, and packed-index boundaries are not regression-tested

**Medium severity, confirmed.** `run_job` only pulses `start` while idle, waits for one observed `done`, and requires `config_error` low (`Apps/Mulein/tests/rtl/mulein_closure_core_tb.sv:140-166`). It does not check reset during work, starts while busy, one-cycle `done`, invalid configuration/descriptors, error recovery, or back-to-back jobs. The ideal combinational stores at `:23-40` have no address/response assertions, and provenance checks cover only packed slots 0 and 1, allowing stale descriptor/trail pairing, upper-index errors, or sticky handshake outputs to escape.

Add cycle-level assertions around `busy`, `done`, and `config_error`; drive unique rows at steps 0 and `MAX_STEPS-1`; cover edge `MAX_EDGES-1`; and assert descriptor/trail pairing across forward/reverse cycles. Keep an Icarus seed-0/seed-25 packed-index test and the Yosys synthesis check for accesses at `Apps/Mulein/rtl/mulein_closure_core.sv:132-149`, `:282-291`, and `:381-386`.

## The compatibility include is resolved from the caller's working directory

**Low severity, confirmed.** `mulein_closure_core.v:1-7` includes `Apps/Mulein/rtl/mulein_closure_core.sv` with a CWD-relative path. Compiling `/Volumes/Code/HELUT/mulein_closure_core.v` succeeds from the repository root and fails from `/tmp` with “Include file ... not found.”

If consumers should invoke this entry point by path, publish a file list/build command that supplies the repository root as an include directory, or point manifests directly at the canonical `.sv`. Otherwise document and regression-test the repository-root CWD precondition.
