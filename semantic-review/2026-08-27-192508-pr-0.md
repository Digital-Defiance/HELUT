# Schema-4 conjugated center and transported-mask migration

This unstaged migration replaces the rejected reserved-pair center with a profile-bound counter-mask XOR between the forward and inverse rotor paths, then carries that contract through Swift, AXI/RTL, Rust, fixtures, and the TensorLUT stand-in cone. The center formula, accepted-beat counter schedule, `UInt64` exhaustion boundary, schema-3 rejection, and archived fixture preservation agree in the reviewed implementations and focused validation. The KAT directory is staged and replaced as a unit, but the profile and KAT still have separate publication points, so the canonical schema-4 release can be left internally incompatible. E256-003 remains OPEN pending human acceptance; this review is not that acceptance.

Watch for: **confirmed — split profile/KAT promotion:** the new profile override can publish a canonical KAT under a noncanonical profile, and interruption between independent profile and bundle replacements creates the same mixed release.

**Verdict**: NEEDS_CHANGES

## High-level view

The host owns the HMAC-derived mask schedule and transports one mask with one absolute byte counter per accepted byte. Swift, Rust, AXI, and core RTL place the mask at the same conjugated center; stale, future, and exhausted counters do not move RTL state.

Fixture-v4 removes reflector storage, adds mask and counter traces, and binds each bundle to canonical profile bytes and hash. Verification independently rederives the cryptographic and fixture state; archived fixture-v3 bytes were preserved exactly and schema-3 identities fail closed.

The release workflow has only per-artifact atomicity. The CLI can activate an arbitrary profile and then replace the default canonical KAT, while profile emission remains a separate operation with no shared commit point or rollback.

The TensorLUT scramble fragment remains a frozen stand-in rather than the full E256 core or an HMAC implementation. Its transported `center_mask` matches the Swift oracle on the synthesized baseline; checked-in TensorLUT artifacts remain the narrower step/NLFF cones.

### Conjugated center and exhausted-counter contract

The design boundary is consistent: the host derives `k_i`, forward rotors compute `A_i(x)`, the center applies XOR, and reverse rotors compute `A_i^-1(A_i(x) XOR k_i)`. Swift derives or accepts the mask and increments only after an accepted byte (`Sources/HELUTCore/Enigma256.swift:316-364`); the AXI driver writes counter and mask before payload (`Sources/HELUTCore/Enigma256AXI.swift:121-143`). RTL applies the XOR after rotor four and snapshots payload, mask, and counter before optional jitter (`Hardware/RTL/Enigma256/enigma_256_core.v:124-141`, `Hardware/RTL/Enigma256/enigma_256_axi.v:220-260`). Rust independently derives and verifies the same schedule (`Reference/Rust/src/e256.rs:527-563`, `Reference/Rust/src/e256.rs:939-986`, `Reference/Rust/src/e256.rs:1056-1067`).

Usable indices are `0...UInt64.max - 1`: the final accepted byte advances state to `UInt64.max`, which is exhausted rather than wrapped. RTL requires an exact supplied counter and excludes `64'hffff_ffff_ffff_ffff`; rejection leaves output-valid, offsets, LFSR, and counter unchanged (`Hardware/RTL/Enigma256/enigma_256_core.v:163-180`). Swift, Rust, and directed RTL tests cover this boundary (`Tests/HELUTTests/Enigma256Tests.swift:248-261`, `Hardware/Testbenches/Enigma256/enigma_256_center_tb.v:116-187`).

The 1,024-byte Swift, Rust, core RTL, and AXI runs matched, including mask, center input/output, and before/after counter traces. The stand-in sources both accept an explicit byte mask (`Sources/HELUTToolKit/Enigma256TensorLUT.swift:218-236`, `Hardware/RTL/Enigma256/enigma_256_scramble_frag_combo.v:16-18`, `Hardware/RTL/Enigma256/enigma_256_scramble_frag_combo.v:120-134`); a synthesized-netlist smoke evaluated 7,056 mask-bearing rows with `baseline_crypto: 0.000000` and `baseline_sanity_pass: true`.

### Fixture-v3 preservation and schema-4 rejection

The loader validates the active profile, rejects schema-3 identities, independently derives the message and nine tables, regenerates ciphertext and every trace, then verifies exact manifest membership and hashes (`Sources/HELUTCore/Enigma256Bridge.swift:261-436`, `Sources/HELUTCore/Enigma256Bridge.swift:545-595`). Embedding canonical profile bytes and SHA-256 prevents interpretation under a different profile (`Sources/HELUTCore/Enigma256Bridge.swift:246-250`).

Every archived fixture-v3 artifact matched the pre-migration index (`historical_mismatches=0`). Swift rejected a synthetically downgraded manifest, Rust rejected a schema-3 profile, and the Rust CLI verified schema 4 with 1,024 bytes, nine tables, ten traces, and 25 artifacts. Generating twice over one temporary destination also exercised replacement of an existing valid KAT.

### A scratch profile can publish the canonical KAT

**Confirmed:** the added command loads and activates `--enigma256-genes`, but `--enigma256-out` still defaults independently to `Fixtures/enigma256_golden`; the resulting bundle is verified against the same supplied profile (`Sources/HELUTToolKit/Enigma256Commands.swift:8-26`). This invocation therefore succeeds while making the two canonical artifacts disagree:

```text
helut --enigma256-golden --enigma256-genes build/scratch-profile.json
# writes Fixtures/enigma256_golden; does not update Fixtures/enigma256_generation.json
```

The bundle writer stages and swaps only that directory (`Sources/HELUTCore/Enigma256Bridge.swift:160-182`). Profile JSON and its Verilog include are also replaced separately (`Scripts/e256_nlff_emit.py:194-199`, `Scripts/e256_nlff_emit.py:243-244`), so interruption during the intended multi-command workflow produces the same split even without the override misuse. Because schema 4 binds the KAT to the profile hash, normal verification then rejects the canonical pair until a manual repair completes.

The new test covers failure inside KAT staging only (`Tests/HELUTTests/Enigma256Tests.swift:489-506`). Add a coordinator that stages and validates profile, include, and KAT as one versioned release and publishes one pointer/rename, or supplies rollback across canonical paths. At minimum, guard canonical output against a noncanonical profile and add an interruption test between profile and KAT publication.
