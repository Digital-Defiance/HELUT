# Canonical E256 KAT publication guard

This follow-up moves implicit golden generation out of the canonical fixture tree and gates explicit canonical publication on the supplied profile’s full compatibility key. Replaying the formerly dangerous invocation with a valid mismatched schema-4 profile produced only `build/hardware/Enigma256/enigma256_golden`; the canonical manifest retained its `fa246e…` identity. Both focused tests pass, and a split profile/KAT pair is rejected with `profileMismatch`.

Watch for: **confirmed — review boundary:** E256-003 remains OPEN pending human review; this pass approves only the split-publication safety follow-up.

**Verdict**: APPROVED

## High-level view

Golden generation now defaults to the build-tree scratch bundle, so custom `--enigma256-genes` input no longer inherits the canonical destination. The CLI replay generated a mismatched `7989fcd5…` scratch manifest without changing the canonical `fa246e9c…` manifest.

An explicit canonical destination resolves to the protected path and requires exact compatibility-key equality before profile activation or bundle staging. Mismatched profiles fail before the writer reaches `Fixtures/enigma256_golden`.

Verification binds both `session.json` and `manifest.json` to the selected profile. An interrupted promotion can leave a mismatched pair on disk, but consumers reject it; the two regressions cover the canonical guard and this fail-closed split state.

### Scratch default removes the concrete overwrite path

`runEnigma256Golden` now chooses `build/hardware/Enigma256/enigma256_golden` unless `--enigma256-out` is supplied (`Sources/HELUTToolKit/Enigma256Commands.swift:35-43`). This former bad command shape therefore no longer selects the canonical bundle:

```text
helut-e256 --enigma256-golden --enigma256-genes build/review-mismatched-enigma256-generation.json
```

The replay used a valid fixture-v4 profile with compatibility key `E256/v2/gen0/7989fcd5…/fixture-v4`. Its bundle landed at the scratch default, while `Fixtures/enigma256_golden/manifest.json` remained `E256/v2/gen0/fa246e9c…/fixture-v4`.

### Explicit canonical publication is checked before mutation

`enigma256ValidateGoldenPublication` standardizes and resolves both paths, allows scratch destinations, and requires compatibility-key equality when the output resolves to the canonical fixture directory (`Sources/HELUTToolKit/Enigma256Commands.swift:8-33`). The command calls it before `profile.activate()` and `writeGoldenBundle` (`Sources/HELUTToolKit/Enigma256Commands.swift:44-67`).

`testCanonicalGoldenPublicationRejectsMismatchedProfile` confirms that a substituted profile hash is rejected at the canonical URL but allowed at a temporary scratch URL (`Tests/HELUTTests/Enigma256Tests.swift:510-546`). It passed; the CLI replay separately covers the new default end to end.

### Split releases fail closed at the profile boundary

`loadAndVerify` compares the session compatibility object with the complete expected profile identity before deriving message state, while manifest verification independently requires the same compatibility key, profile hash, and canonical profile bytes (`Sources/HELUTCore/Enigma256Bridge.swift:263-289`, `Sources/HELUTCore/Enigma256Bridge.swift:539-620`). A stale KAT paired with a newly promoted profile cannot pass either boundary.

`testProfileKATSplitPublicationFailsClosed` changes a valid bundle’s serialized `profile_sha256` and confirms loading throws `BridgeError.profileMismatch` without deleting the bundle (`Tests/HELUTTests/Enigma256Tests.swift:547-584`). It passed. Publication is still non-transactional, but an interrupted mismatch is unavailable rather than accepted.
