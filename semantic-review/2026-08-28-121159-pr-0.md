# E256-v3 immutable research profile and fixture-v5 boundary

This tranche adds a package-scoped, incompatible E256-v3/gen0 Swift profile, deterministic fixture-v5 authoring/verification, an independently written in-tree Rust rederivation, and a versioned RTL/MMIO lane. The positive path exercises profile identity, derivation, recurrence, a 1,024-byte trace, reciprocal operation, zero-load rejection, and Rust/RTL agreement. The freeze is not ready to accept because the fixture schema can decouple verifier artifacts from RTL artifacts, configuration faults remain data-active, and several strictness claims exceed what the gates enforce. E256-003 remains **OPEN**; local parity is implementation evidence only, not a security proof or independent external acceptance, and standard AEAD remains required for real data.

Watch for: **confirmed** manifest-controlled artifact bindings can let local gates consume different evidence; **confirmed** rejected or interrupted configuration does not quiesce the datapath; **confirmed** Swift and Rust accept different domain/manifest languages.

**Verdict**: NEEDS_CHANGES

## High-level view

The Swift lane is isolated from the legacy mutable selector and keeps the reciprocal construction package-scoped with `standard_aead_required` frozen into the profile. Its indexed-domain parser is looser than `index_u8_2dec`, admitting signed aliases that Rust rejects.

Fixture-v5 rederives keys, state, tables, recurrence, stream, trace, and reciprocal decrypt. Its descriptor array nevertheless defines its own accepted layout, while paths are not bound to logical IDs; Swift/Rust can verify one artifact and RTL can consume another. Rust also omits Swift's byte-canonical JSON check.

The MMIO plan validates malformed input before its first write. After programming begins, there is no abort/commit boundary, and the RTL wrapper forwards traffic while `configuration_error` is set, allowing stale or mixed configuration to remain data-active.

The positive staged fixture passes all three implementations. Negative-vector counts, the standalone RTL runner, the shared-source NLFF comparison, and the v3 HKDF test still leave self-referential or non-executed evidence.

## Fixture-v5 does not bind canonical paths to logical artifacts — HIGH

**Confirmed.** Artifacts independently supply `path` and `logicalID` (`Sources/HELUTCore/Enigma256FixtureV5.swift:211-214`). Swift builds the accepted path set from those descriptors and indexes bytes only by logical ID (`Sources/HELUTCore/Enigma256FixtureV5.swift:568-615`); Rust repeats that design (`Reference/Rust/src/e256_v3.rs:428-476`). Neither verifier freezes the 26 descriptor tuples, rejects unknown logical IDs, requires the raw/hex pairs, or binds `artifacts/stream-trace.csv` to `stream_trace`.

Swift checks the canonical stream pathname but retrieves the verified trace from `decodedByLogical["stream_trace"]` (`Sources/HELUTCore/Enigma256FixtureV5.swift:848-856`); RTL opens the pathname directly (`Hardware/Testbenches/Enigma256/enigma_256_v3_fixture_tb.v:100-119`). A manifest can therefore place a correct verifier trace under another path and a self-authored RTL trace at the canonical path under an unknown logical ID. Table paths have the same split. Tests assert 26 only for the good bundle and reject an *unlisted* extra (`Tests/HELUTTests/Enigma256FixtureV5Tests.swift:69`, `:205-210`), not a descriptor-backed extra or remap. Freeze the schema-derived path/logical-ID/encoding set in both verifiers and test both mutations before RTL runs.

## Rejected RTL configuration remains data-active — HIGH

**Confirmed.** The wrapper records a zero-state load and suppresses only `load_state` (`Hardware/RTL/Enigma256/enigma_256_core_v3.v:36-46`, `:56`), while forwarding `valid_in` unchanged (`:66`). The test accepts counters 1 and 2 after the malformed load while the error remains set (`Hardware/Testbenches/Enigma256/enigma_256_v3_tb.v:158-169`). Traffic can consequently run under the prior state—or before any accepted v3 load after reset—if control software misses the status bit. Gate accepted traffic and `valid_out` behind a successfully armed configuration, and test reset-before-load plus rejected-load-then-traffic.

## MMIO programming has no failure-atomic commit — HIGH

**Confirmed.** `program(into:)` performs 2,304 throwing table writes before the throwing state load (`Sources/HELUTCore/Enigma256V3MMIO.swift:105-128`). A sink failure preserves earlier side effects with no rollback, invalidation, or abort callback, leaving the old session able to use mixed tables. Tests cover a nonthrowing success and validation failure before write zero only (`Tests/HELUTTests/Enigma256V3MMIOTests.swift:17-35`, `:129-168`). Use shadow slots plus commit, or quiesce before write zero and require abort/re-arm after any failure; inject failures at table boundaries and before `loadState`.

## Swift accepts noncanonical indexed-domain aliases — MEDIUM

**Confirmed.** The profile freezes `day/rotor/{index_u8_2dec}` (`Sources/HELUTCore/Enigma256V3.swift:125`) but parses the two-character suffix with `Int` (`:188-192`). Swift accepts `+0` and `-0`; Rust uses exact frozen strings (`Reference/Rust/src/e256_v3.rs:1081-1085`). Tests reject only `day/rotor/16` and an unknown word (`Tests/HELUTTests/Enigma256V3Tests.swift:58-59`). Require two ASCII digits and canonical zero-padding, then test signed, space-padded, and non-padded forms.

## Rust accepts manifests Swift rejects — MEDIUM

**Confirmed.** Swift requires decoded data to re-encode byte-for-byte as sorted pretty JSON with one LF (`Sources/HELUTCore/Enigma256FixtureV5.swift:563-565`). Rust checks one trailing LF/no CR and then uses `serde_json::from_slice` (`Reference/Rust/src/e256_v3.rs:420-426`), accepting reordered keys and alternate whitespace. Implement the same canonical-byte rule in Rust and run one noncanonical corpus against both consumers.

## Negative-vector verification is mostly metadata — MEDIUM

**Confirmed.** Swift requires 13 labels but executes four mutations; the plugboard case accepts any `Enigma256V3Error` (`Sources/HELUTCore/Enigma256FixtureV5.swift:894-940`). Rust executes none, checking IDs, expected-error strings, and nonempty descriptions (`Reference/Rust/src/e256_v3.rs:909-934`), while parity asserts the returned count (`Reference/Rust/tests/e256_v3_parity.rs:23-24`). Separate Swift tests cover the failure classes, but the fixture report and independent Rust pass do not prove those fixture mutations fail closed. Encode and execute each mutation in both consumers, or rename the field as a declaration count; assert exact errors where named.

## Standalone RTL parity can use an unverified, shared-source oracle — MEDIUM

**Confirmed.** The runner accepts a fixture after checking only that its manifest exists (`Scripts/enigma256_v3_sim.sh:10-13`) and launches the path-based bench without invoking a verifier (`:29-34`). The bench hard-codes message state and reads tables/trace directly (`Hardware/Testbenches/Enigma256/enigma_256_v3_fixture_tb.v:4-18`, `:100-119`), so a fixture authored from RTL can produce a standalone 1,024/1,024 PASS.

The NLFF comparison is structural: v3 textually includes the v2 equations (`Generated/Profiles/Enigma256/enigma_256_nlff_v3.vh:9`), then the bench compares v2 and v3 wrappers (`Hardware/Testbenches/Enigma256/enigma_256_v3_tb.v:68-75`). It proves shared source resolution, not agreement with the frozen Swift/Rust formula. Verify the exact selected fixture before simulation and drive broad, independently generated NLFF expected masks into RTL.

## The v3 HKDF known-answer test checks only length — LOW

**Confirmed.** `hmac_and_hkdf_match_rfc_vectors` computes HKDF-SHA512 but asserts only `okm.len() == 42` (`Reference/Rust/src/e256_v3.rs:1413-1426`). Any incorrect 42-byte result passes. Staged parity detects disagreement with current Swift output but does not independently establish `hkdf_sha512_rfc5869_v1`; assert the complete RFC OKM and an HMAC-SHA512 known answer.

## Validation run and claim boundary

`swift test --filter 'Enigma256(V3|FixtureV5)'` ran 17 scoped tests with zero failures and one opt-in emitter skipped. `cargo test --test e256_v3_parity` plus `cargo test e256_v3::tests` passed one staged parity and two v3 unit tests. `bash Scripts/enigma256_v3_sim.sh` reported PASS for zero-state/NLFF and 1,024-beat fixture benches. These receipts do not close E256-003, establish security, provide independent external acceptance, or make the raw reciprocal stream suitable for real data.
