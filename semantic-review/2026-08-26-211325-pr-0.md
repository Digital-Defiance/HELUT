# Reconstructible, independently validated TensorLUT receipts

This follow-up closes both Medium blockers from the prior review. Receipt runs now archive exact Package/Sources and orchestration bytes, including untracked files, behind a hashed inventory and aggregate digest. Swift exposes raw canonical and recovered planted entries; Python parses those finite values and independently derives the `<=1e-6` predicate before accepting the control. Source pinning, fail-closed completion, control semantics, path containment, and full-versus-bounded budgets remain intact.

Watch for: **confirmed, Low residual risk** the Python validator has no newly added focused unit tests; complete dual-cone receipts mitigate this and it is not a shipping defect.

**Verdict**: APPROVED

## High-level view

Receipt provenance is reconstructible rather than hash-only. `Package.swift`, optional `Package.resolved`, all files under `Sources`, the profile fixture, runner, wrappers, synthesis script, five RTL inputs, and generated profile include are copied into each run; per-file hashes, an aggregate digest, and a separately hashed archive manifest bind the bundle.

The executable no longer self-certifies planted recovery. Swift reports canonical and final entry values; Python requires both to be finite, computes the error and threshold itself, and rejects disagreement with Swift's Boolean or aggregate control result.

Execution stays fail-closed and profile-bound: build inputs are compared around compilation, `HELUT_BIN` is rejected, the copied binary is checked around each arm, interruptions cannot publish a pass, and resolved run paths remain inside the profile namespace. Full historical budgets are still the default, with a separate explicit bounded matrix.

Both final receipts are tied to the reviewed bytes and report `status=pass`, complete 11/11 rows, four controls, seven current `blue_hold`, and zero current `red_pressure`. Independent checks rehashed 33 row artifacts and 120 archived inputs per cone; Enigma256 tests passed 43/43, and the supplied Yosys checks reported zero problems.

## Raw planted entries close the self-certified recovery gap

Swift reads the canonical and polished values from the planted LUT entry, computes a finite absolute error, includes exact recovery in `controlPass`, and emits both raw values plus its derived result (`Sources/HELUTToolKit/Enigma256TensorLUT.swift:743-774, 811-814`). Python parses the raw values through `finite_float`, derives `abs(final - canonical) <= 1e-6`, cross-checks Swift's Boolean, and uses its own predicate in `derived_control_pass` (`Scripts/enigma256_tensorlut_battery.py:529-564`). The values and independently computed error are retained in each receipt row (`Scripts/enigma256_tensorlut_battery.py:596-612`).

Control scope remains honest. Planted arms require a live one-nonbinary defect, a threshold-near-binary fit, and exact recovery; contradictory-null arms add one conflicting duplicate and only calibrate no-false-positive verdict plumbing (`Sources/HELUTToolKit/Enigma256TensorLUT.swift:485-505, 724-776`; `Scripts/enigma256_tensorlut_battery.py:518-574`). Current `red_pressure` exits 2 and fails the battery instead of being normalized into success, while report language limits `blue_hold` to bounded in-sample optimizer failure rather than security evidence (`Scripts/enigma256_tensorlut_battery.py:576-633`; `Sources/HELUTToolKit/Enigma256TensorLUT.swift:797-833`).

## Pinning, interruption, containment, and matrices remain fail-closed

Receipt mode rejects `HELUT_BIN`, pins the built executable, and checks its hash before and after every arm (`Scripts/enigma256_tensorlut_battery.py:259-313, 396-459`). Run IDs are single safe components, resolved paths must remain below the profile root, and existing run directories cannot be reused (`Scripts/enigma256_tensorlut_battery.py:640-662`). `BaseException` preserves interrupted/failed state, and even normal completion is downgraded unless row count equals the matrix and every row has `outcome_ok is True` (`Scripts/enigma256_tensorlut_battery.py:706-770`).

The seven historical full tuples remain separate from the seven checkpoint tuples; `--budget-profile` defaults to `full` and only explicit `bounded` selects the reduced set (`Scripts/enigma256_tensorlut_battery.py:40-61, 642-644, 687-689`). Both wrappers forward arguments and state the full-by-default contract (`Scripts/enigma256_red_battery.sh:2-6`; `Scripts/enigma256_scramble_frag_battery.sh:2-7`).
